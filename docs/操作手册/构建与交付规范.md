# HyperCode 构建与交付规范

本文档用于指导 HyperCode 的 CLI 与 VSIX 构建、冒烟验证和产物验收。

如果你是在执行一次完整的 upstream sync，本手册只负责构建与产物验收部分；同步主流程与 merge-back 判断统一按 [上游同步操作流程](上游同步操作流程.md) 执行。

## 目标与产物范围

当前纳入本手册范围的产物：

- Windows CLI 二进制
- Windows x64 CLI + VSIX 一体化离线包
- Ubuntu 20.04 x86_64 CLI 离线包
- VSCode VSIX

当前不在本手册范围内：

- npm
- Homebrew
- AUR
- Nix
- 源码安装分发
- Marketplace 自动化重写

## 构建前提

执行构建前，先确认：

```txt
仓库处于可工作的源码状态
不把旧的 dist / release 产物当作本次构建结果
需要构建 VSIX 时，明确 sdks/vscode 不属于根 workspace
```

VSIX 特别说明：

```txt
不要假定根目录的 bun install 会准备好 VSCode 扩展依赖。
在打包 VSIX 之前，必须先进入 sdks/vscode 单独安装依赖。
```

## CLI 构建

执行：

```powershell
cd D:\project\hypercode\packages\opencode
bun run build --single
```

如果这一步失败，不继续做 CLI 产物验收。

## CLI 冒烟与通过标准

回到仓库根目录验证生成的 EXE：

```powershell
cd D:\project\hypercode

.\packages\opencode\dist\hypercode-windows-x64\bin\hypercode.exe --help
.\packages\opencode\dist\hypercode-windows-x64\bin\hypercode.exe --version
```

通过标准：

```txt
--help 必须显示 HyperCode
--version 必须成功
dist 目录必须为 hypercode-windows-x64
exe 文件必须为 hypercode.exe
```

## CLI 手工验收

在 `--help` 和 `--version` 通过后，再做一次最小人工验收：

```txt
直接启动 hypercode.exe
确认首页与首屏品牌显示为 HyperCode
确认没有出现 license 授权阻断
如果需要进入 TUI，确认用户可见入口没有退回 OpenCode 叙事
```

这一节只要求最小可见面确认，不替代完整功能测试。

## Windows 一体化离线包

在联网的 Windows 构建机上，从仓库根目录执行：

```powershell
cd D:\project\hypercode
bun run build:offline-windows
```

该命令会构建 Windows x64 标准版、baseline 兼容版和 VSIX，并生成：

```text
release-artifacts/hypercode-offline-windows-x64-1.17.3.zip
release-artifacts/hypercode-offline-windows-x64-1.17.3.zip.sha256
```

如果目标机未安装 VS Code 或 Git，可在构建时把官方离线安装器一起装入交付包：

```powershell
bun run build:offline-windows -- `
  --vscode-installer D:\installers\VSCodeUserSetup-x64.exe `
  --git-installer D:\installers\Git-64-bit.exe
```

目标机完整解压 ZIP 后只需运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

也可以双击 `install.cmd`。安装脚本会校验包内文件、自动选择标准版或 baseline、安装 CLI 和 VSIX、设置用户 PATH、关闭公网模型目录刷新与自动更新，并输出 License 机器码。拿到目标机 License 后可幂等补装：

```powershell
.\install.ps1 -LicensePath D:\transfer\license.txt
```

默认配置仍为 `minimax-direct/MiniMax-M2.7`，但其地址是公网 `https://api.minimaxi.com/v1`。无外网目标机只能进行 CLI、VSIX、License 和界面调试，模型调用必须通过可达的内网代理或模型网关。包内同时提供内网 OpenAI-compatible 模板；服务就绪后可运行：

```powershell
.\install.ps1 `
  -Provider Internal `
  -InternalBaseUrl "http://model-gateway:8000/v1" `
  -InternalModelId "MODEL_ID" `
  -InternalApiKey "INTERNAL_KEY" `
  -ForceConfig
```

## Ubuntu 20.04 离线 CLI 构建

Ubuntu 离线包必须使用 HyperCode 专用构建命令。不要运行仓库根目录的 `install` 脚本，也不要运行 README 中的在线安装命令；它们目前仍指向上游 OpenCode 下载地址，不能用于 HyperCode 交付。

在联网的 Windows 构建机上，从仓库根目录执行：

```powershell
cd D:\project\hypercode
bun run build:offline-linux -- --version 1.17.3
```

版本号必须是合法 SemVer，并应与本次交付版本一致。该命令会：

- 交叉构建 `hypercode-linux-x64` 标准版
- 交叉构建 `hypercode-linux-x64-baseline` 兼容版
- 固定嵌入空的公网模型目录，现场模型只从内网 `hypercode.json` 注册
- 下载并校验与项目 Bun 版本匹配的官方 Linux 编译器资产，缓存在 `node_modules/.cache`
- 清除子构建的发布标志，不上传 GitHub
- 在 `release-artifacts` 下生成离线包和外部 SHA-256 文件

产物示例：

```text
release-artifacts/hypercode-offline-ubuntu20.04-x64-1.17.3.tar.gz
release-artifacts/hypercode-offline-ubuntu20.04-x64-1.17.3.tar.gz.sha256
```

离线包包含：

```text
bin/hypercode
bin/hypercode-baseline
install.sh
install-license.sh
config/hypercode.json.example
config/hypercode.env.example
README.zh-CN.md
SHA256SUMS
```

## Ubuntu 离线安装

先在联网构建机或受控中转机核对外部 SHA-256，再通过 U 盘复制到目标 Ubuntu 虚拟机。目标机以最终运行 HyperCode 的普通用户登录：

```bash
tar -xzf hypercode-offline-ubuntu20.04-x64-1.17.3.tar.gz
cd hypercode-offline-ubuntu20.04-x64-1.17.3
./install.sh
export PATH="$HOME/.local/bin:$PATH"
hypercode --version
```

安装器默认写入 `~/.local/bin/hypercode`，不使用网络或 `sudo`。它会检查 x86_64、glibc 和二进制 SHA-256，并根据 `/proc/cpuinfo` 自动选择标准版或 baseline。现场也可强制选择：

```bash
./install.sh --variant standard
./install.sh --variant baseline
./install.sh --install-dir "$HOME/bin"
```

## Ubuntu License 流程

License 与目标虚拟机的 `/etc/machine-id` 绑定。必须先完成虚拟机克隆和最终部署，确认 machine-id 不再变化，再执行：

```bash
hypercode license machine-id
```

将机器 ID 带回管理员电脑签发 `license.txt`，再通过 U 盘导入：

```bash
./install-license.sh /media/usb/license.txt
hypercode license status
```

脚本会把 License 安装到 `~/hyper-aicode/license.txt`，目录权限为 `700`，文件权限为 `600`。如果虚拟机被重新克隆或 `/etc/machine-id` 发生变化，必须重新签发。

## Ubuntu 内网模型配置

离线包只提供模板，不携带内网地址和真实密钥：

```bash
mkdir -p ~/.config/opencode
[ -e ~/.config/opencode/hypercode.json ] || cp config/hypercode.json.example ~/.config/opencode/hypercode.json
[ -e ~/.config/opencode/hypercode.env ] || cp config/hypercode.env.example ~/.config/opencode/hypercode.env
chmod 600 ~/.config/opencode/hypercode.json
chmod 600 ~/.config/opencode/hypercode.env
```

修改 `baseURL`、`MODEL_ID` 和密钥占位值，再加载隔离环境：

```bash
. ~/.config/opencode/hypercode.env
```

环境模板默认设置 `HYPERCODE_DISABLE_MODELS_FETCH=1`，避免运行时访问公共 `models.dev`。将加载命令加入目标用户的 shell 配置，或在每次运行 HyperCode 前加载。

安装后依次验收：

```bash
hypercode license status
hypercode debug config
hypercode models internal
hypercode run -m internal/MODEL_ID "回复ok"
```

升级时使用新版本离线包重新运行 `./install.sh` 覆盖二进制。用户 License 和 `~/.config/opencode/hypercode.json` 不在安装目录内，不会被覆盖。

## VSIX 依赖准备

先安装 `sdks/vscode` 自身依赖：

```powershell
cd D:\project\hypercode\sdks\vscode
bun install
```

如果跳过这一步，常见失败信号包括：

```txt
Cannot find module 'vscode'
Cannot find name 'setTimeout'
Cannot find name 'fetch'
```

## VSIX 打包

在 `sdks/vscode` 下执行：

```powershell
cd D:\project\hypercode\sdks\vscode

bun run package
npx --yes @vscode/vsce package `
  --no-git-tag-version `
  --no-update-package-json `
  --no-dependencies `
  --skip-license `
  -o dist/hypercode.vsix
```

如果打包命令失败，不继续做 VSIX 验收。

## VSIX 验收

解包并检查打包好的 VSIX：

```powershell
Remove-Item -Recurse -Force D:\test\hypercode-vsix-inspect -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force D:\test\hypercode-vsix-inspect

Copy-Item `
  .\sdks\vscode\dist\hypercode.vsix `
  D:\test\hypercode-vsix-inspect\hypercode.zip `
  -Force

Expand-Archive `
  D:\test\hypercode-vsix-inspect\hypercode.zip `
  -DestinationPath D:\test\hypercode-vsix-inspect\unzipped `
  -Force
```

搜索解包后的用户可见残留：

```powershell
rg -n "opencode --port|opencode for VS Code|""title"".*opencode|""category"".*opencode" D:\test\hypercode-vsix-inspect\unzipped
```

通过标准：

```txt
不得存在 opencode --port
不得存在用户可见的 opencode for VS Code
内部 opencode.* command id 可以保留
```

## 产物清单

CLI 产物：

- `packages/opencode/dist/hypercode-windows-x64/bin/hypercode.exe`
- 发布用的 zip/tar 产物名使用 `hypercode-*`

VSIX 产物：

- `sdks/vscode/dist/hypercode.vsix`

## 兼容性保留项

以下内容属于兼容性保留，不应在本手册覆盖的构建交付过程中被顺手改掉：

- `opencode` CLI 别名
- `@opencode-ai/*` 包名
- `packages/opencode` 目录名
- 上游同步脚本与署名归属

## 常见失败信号

遇到以下情况时，视为本轮构建或交付验收未通过：

```txt
CLI build --single 失败
hypercode.exe --help / --version 失败
CLI 手工验收未通过
sdks/vscode 未先 bun install 就开始打包
vsce package 失败
VSIX 解包后仍存在用户可见的 opencode 残留
产物名称不是 hypercode-windows-x64 / hypercode.exe / hypercode.vsix
```
