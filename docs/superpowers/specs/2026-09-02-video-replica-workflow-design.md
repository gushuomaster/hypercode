# HyperCode 豆包产品视频复刻工作流设计

## 目标

在 Windows 桌面版 HyperCode 中接入当前用户已安装的 `doubao-video-replica` 个人 skill，使用户可以在聊天中提交参考视频和产品参考图，完成视频分析、分镜审批、首帧生成与质检，并获得逐段豆包提示词。

首版不调用豆包、不操作豆包网页、不生成或拼接视频。ChatGPT Plus 只作为人工图片生成兜底，任何自动图片生成都使用公开、可编程且独立计费的服务。

## 已确认产品决策

- 首版仅支持 Windows 桌面应用，主要服务当前电脑，不随 HyperCode 对外分发 skill。
- 自动识别“参考视频 + 替换产品图”的意图，同时允许显式调用 `doubao-video-replica`。
- 用户首次启动任务时选择输出目录，后续从该目录中的结构化状态续接。
- 超过 60 秒的参考视频拆为不超过 60 秒的章节，逐章审批和生成。
- 免费编排模型优先；免费模型之间可自动切换并通知用户；升级 ChatGPT Plus 前必须确认。
- 免费模型通过可信 provider 白名单、能力筛选和健康检查动态发现；新模型首次真实使用前必须确认。
- 免费图片池固定优先级为 `qwen/qwen-image-edit`、`black-forest-labs/flux_1-kontext-dev`，且模型必须支持参考图输入或图片编辑。
- 免费图片池失败后，按生成波次展示失败分段、图片张数和预计费用，经用户确认后才能使用 `gpt-image-1-mini`。
- 更高质量图片模型是二次付费升级，同样按波次确认。
- 图片验收采用严格规则：产品文字、Logo、形状、接口和配色出现明显偏差即失败。
- 主免费编排模型执行质检；结论不确定时由另一个免费模型复核；用户拥有最终决定权并可记录风险后强制接受。
- 用户拒绝某张首帧时，只重新生成对应分段，记录原因并保留旧版本。
- Plus 人工生成的图片由用户上传回当前聊天，系统自动匹配分段并请求用户确认。
- 凭据优先使用 HyperCode 凭据存储，环境变量作为兜底；项目状态、日志和前端不得保存明文密钥。
- Python 依赖缺失时，先征得用户确认，再创建隔离虚拟环境安装。

## 范围划分

本设计分为三个可独立验证的垂直切片。每个切片完成后都能保持应用可运行，并且可以单独回滚。

### 切片一：基础接入

1. 发现当前 Windows 用户目录下的 Codex 个人 skills。
2. 让 `doubao-video-replica` 通过现有 `skill` 工具加载，不复制、不修改 skill 文件。
3. 建立独立图片生成服务与 `image_generate` 工具。
4. 支持 NVIDIA 免费图片模型和 OpenAI `gpt-image-1-mini`。
5. 生成图片立即落盘，并作为工具附件回显到当前聊天。

### 切片二：路由、审批与恢复

1. 建立编排模型池和图片模型池的纯策略模块。
2. 从 `models.dev` 目录筛选免费模型，冻结任务级候选快照。
3. 复用聊天问题生命周期承载新模型首次使用、付费升级、依赖安装和图片验收。
4. 为问题请求增加可选的图片附件和结构化摘要，桌面聊天中显示缩略图、费用、风险和分段编号。
5. 通过结构化检查点恢复，不要求新模型重新理解完整聊天。

### 切片三：工作流协调与质检

1. 增加视频复刻工作流服务，负责调用 skill 脚本、校验状态和记录阶段。
2. 自动处理长视频章节、波次调度、失败分段隔离和依赖链暂停。
3. 增加严格图片质检、第二模型复核和用户覆盖记录。
4. 支持用户上传 Plus 生成结果后的分段匹配与确认。
5. 从 skill 的结构化状态编译最终交付，不在代码中重写 skill 的分镜业务规则。

## 架构边界

### 个人 skill 发现

现有 `packages/opencode/src/skill/index.ts` 已扫描 `.claude/skills`、`.agents/skills`、配置目录和显式 `skills.paths`，但没有扫描 `.codex/skills`。

首版增加 Windows 用户级 `~/.codex/skills/**/SKILL.md` 扫描，并遵守现有 `disableExternalSkills` 开关。扫描只读取 `SKILL.md` 与 skill 工具按需列出的关联文件，不安装、不更新、不删除个人 skill。重名时继续沿用现有的确定性覆盖和告警行为。

该能力是通用个人 skill 兼容层，不写死 `C:\Users\28320`，也不把 `doubao-video-replica` 文件复制到仓库。

### 视频复刻工作流

新增 Location-scoped 的 `VideoReplica` 服务。服务只承担协调职责：

- 检查 Windows、Python、FFmpeg、FFprobe 和 skill 路径；
- 经确认后创建 skill 专用虚拟环境；
- 调用 `init_project.py`、`inspect_video.py`、视觉资产脚本和 `delivery_compiler.py`；
- 读取和校验 `project-state.json`；
- 维护结构化检查点、模型池快照、审批结果与错误状态；
- 将图片生成请求交给 `ImageGeneration` 服务；
- 将质检请求交给模型路由服务。

工作流服务不复制动态语义分段、覆盖审计、视觉资产匹配或最终提示词规则。这些规则继续由外部 skill 及其脚本拥有，避免 HyperCode 与个人 skill 形成两套实现。

### 状态与检查点

外部 skill 的 `project-state.json` 仍是业务状态真值。HyperCode 在其中增加独立命名空间 `hypercode`，只保存集成层状态：

```json
{
  "hypercode": {
    "schema_version": 1,
    "workflow_id": "...",
    "chapter": 1,
    "orchestration_pool": [],
    "image_pool": [],
    "approved_models": [],
    "checkpoint": {
      "phase": "analysis|approval|generation|qc|delivery",
      "segment_ids": [],
      "pending_action": null
    },
    "approvals": [],
    "provider_attempts": []
  }
}
```

不得在该状态中保存 API key、OAuth token、完整聊天记录或未经需要的个人路径。模型切换只从最近一次已落盘检查点继续。

### 编排模型池

模型目录来自现有 `ModelsDev` 服务，不增加新的网络目录。候选必须同时满足：

- provider 在配置白名单中；
- `status` 为 active；
- 输入支持 `text`、`image`、`video`；
- 支持工具调用；
- 输入和输出标价均为零；
- 健康检查能完成最小结构化输出和工具调用。

候选排序首先采用用户配置，其次采用确定性的能力排序。新模型健康检查通过后进入“待确认”状态，用户首次批准后才可参与真实任务。任务启动时冻结候选列表，目录后续刷新只影响新任务。

免费模型切换触发条件：429、服务不可用、视频语义分段不完整、覆盖审计失败、结构化输出连续两次不合法或工具调用连续两次失败。同级切换自动发生并在聊天中通知。免费池耗尽后暂停；使用 ChatGPT Plus 继续编排前必须由用户确认。

### 图片生成服务

新增 `ImageGeneration` 服务和 provider adapter 接口。首版 adapter：

- NVIDIA OpenAI-compatible adapter：`qwen/qwen-image-edit`、`black-forest-labs/flux_1-kontext-dev`；
- OpenAI Images API adapter：`gpt-image-1-mini`，并预留高质量模型 ID 配置。

服务输入包含分段 ID、提示词、最小参考图集合、输出目录、画幅、质量档和任务级模型池快照。输出包含文件路径、MIME、模型、provider、调用次数、耗时和可安全展示的计费元数据。

每段每次请求只生成一张 9:16 图片。默认并发为 4，遇到 429、5xx 或会话错误时降低并发，稳定后逐步恢复。技术错误退避后最多重试一次；成功结果立即原子写入输出目录，失败不得撤销同波次的成功结果。

所有输出文件先写临时文件，解码和格式校验通过后原子改名。输出路径必须位于用户选择的项目目录内，不能覆盖原始参考视频或产品图片。

### 凭据解析

图片 adapter 按以下顺序取凭据：

1. HyperCode 现有 Auth/Account 服务中的 active provider credential；
2. provider 声明的环境变量，例如 `NVIDIA_API_KEY`、`OPENAI_API_KEY`；
3. 缺失时返回可操作错误并引导用户进入现有 provider 凭据界面。

凭据只在后端请求边界使用。日志只记录 provider、模型、状态码、重试与计费信息，不记录请求头、密钥、OAuth token 或完整参考图内容。

### 聊天审批协议

复用现有 `Question` 服务的阻塞、回复、拒绝和事件传播机制。为问题请求增加可选 `presentation`：

- `images`：当前波次或单段的缩略图资源；
- `facts`：分段 ID、张数、模型、预计费用、失败原因、风险；
- `tone`：普通、警告或付费确认。

该字段是通用展示信息，不嵌入视频复刻业务枚举。CLI/TUI 可忽略可选展示字段；首版只在桌面使用的 app renderer 中实现。

付费确认、模型首次使用、依赖安装和最终图片验收分别创建独立问题。分镜仍严格使用 skill 唯一批准句：

```text
批准分镜，开始生成首帧图片。
```

任何其他按钮文案或普通肯定回答都不能替代该批准句。

### 图片质检

质检读取批准分段数据、产品参考图、当前生成图和必要的前置已接受首帧，输出结构化结论：

- 产品文字与 Logo；
- 产品形状、比例、接口和部件；
- 配色和材质；
- 起始状态与主体完整性；
- 场景、手部、物理关系；
- 机位、景别、构图和 9:16 适配；
- 水印、字幕、重复产品和生成瑕疵。

任一硬错误导致失败。主模型返回不确定时才调用免费池中的第二模型复核。每张图片最多进行一次针对性质量重试；仍失败则停止受影响依赖链并请求用户处理。用户可强制接受，但必须展示风险并把覆盖决定、时间和理由写入状态。

### Plus 人工兜底

系统只生成供 ChatGPT Plus 使用的提示词包和参考图清单，不调用 ChatGPT 私有接口。用户将结果上传回聊天后，工作流根据文件名中的可选分段 ID、当前待处理分段和视觉相似证据给出匹配建议。系统必须要求用户确认映射，不能仅凭自动匹配直接接受。

## 数据流

1. 用户提交参考视频、产品图和复刻意图。
2. 模型加载个人 `doubao-video-replica` skill。
3. 工作流请求用户选择输出目录并初始化项目。
4. 用户选择视觉资产入口；工作流调用 skill 脚本分析视频和编译唯一审批包。
5. 用户逐字批准分镜后，工作流冻结 skill 状态与本次模型池快照。
6. 每个生成波次由图片服务先尝试免费模型；失败时按策略降级或申请付费确认。
7. 图片落盘后由主免费模型质检；不确定时第二模型复核。
8. 当前聊天显示波次摘要和缩略图，用户接受、拒绝、强制接受或要求单段重做。
9. 全部可继续分段验收后，skill 编译逐段豆包提示词与性能报告。

## 错误处理

- skill 不存在：停止并提示当前扫描位置和显式配置方法，不静默下载。
- Python 依赖缺失：请求确认；拒绝后停止，不修改系统 Python。
- FFmpeg/FFprobe 缺失、媒体不可读、时间戳不可靠或缓存指纹不匹配：按 skill 契约停止，不猜测。
- 免费编排模型失败：记录失败原因并切换同级候选；池耗尽后请求 Plus 升级确认。
- 免费图片模型失败：保留成功图片；池耗尽后展示待生成张数和预计费用，请求 `gpt-image-1-mini` 确认。
- 付费价格未知或目录价格过期：不得显示虚假估价；标为“无法可靠估算”并要求用户显式确认。
- 图片硬错误：只重试该分段一次；再次失败后暂停该分段及其依赖。
- 用户拒绝图片：保留旧版本，仅重新生成对应分段。
- 应用退出或模型切换：从已落盘检查点恢复，不自动重放已成功的付费调用。

## 安全与隐私

- 用户已允许将产品图和视频抽帧发送给第三方模型服务，但每个 provider 仍必须在调用记录中明确。
- 只发送当前分段的最小参考图集合，不发送整个资产库或无关聊天附件。
- 禁止在前端 bundle、项目状态、日志、异常消息和工具输出中暴露凭据。
- 输出路径进行规范化和工作目录包含检查，拒绝 `..`、盘符切换和符号链接逃逸。
- 原始视频、产品图和个人资产库始终只读；清理仅覆盖本工作流创建且未引用的临时文件。
- 外部 skill 与脚本被视为用户安装的可执行内容，加载前显示来源路径；依赖安装和脚本执行继续受现有工具权限约束。

## 测试策略

所有功能遵循测试先行。

- skill 发现：临时 HOME 中创建 `.codex/skills/<name>/SKILL.md`，验证发现、禁用、重名与路径无硬编码。
- 模型池：使用纯目录夹具测试筛选、排序、弃用模型排除、新模型待确认、任务快照冻结和池耗尽。
- 图片路由：使用本地 HTTP 测试服务验证 NVIDIA/OpenAI 请求转换、凭据优先级、429/5xx 降并发、一次技术重试和付费门。
- 文件输出：验证原子落盘、路径逃逸拒绝、原文件不覆盖、部分成功保留。
- Question 协议：验证旧请求兼容、可选展示字段编码、HTTP API 和 SDK 类型。
- 桌面 UI：组件/数据测试验证缩略图、费用、风险和四种验收决定；不依赖真实网络模型。
- 工作流：使用临时目录和最小假 skill 脚本做端到端测试，验证唯一批准句、检查点恢复、单段重做、长视频分章和 Plus 导入确认。
- 质检：以结构化夹具验证硬错误、第二模型复核、最多一次质量重试和强制接受审计记录。

测试从对应 package 目录运行；类型检查使用 `bun typecheck`，不从仓库根运行测试，也不直接调用 `tsc`。

## 验收标准

1. Windows 桌面版可发现当前用户的 `doubao-video-replica`，且不复制或修改个人 skill。
2. 用户可以从聊天完成输出目录选择、唯一分镜审批、波次生成和图片验收。
3. 免费编排模型和图片模型按确认策略自动发现、健康检查、冻结与切换。
4. 免费图片模型不可用时不会自动产生 OpenAI 费用；确认信息包含张数、失败分段和可得的预计费用。
5. 每个成功图片立即落盘，单段失败不会丢失同波次其他结果。
6. 严格质检和用户最终确认都被记录；每张质量重试不超过一次。
7. API key 不出现在仓库、项目状态、日志或前端。
8. 崩溃或模型切换后从结构化检查点续接，不重复已成功的付费调用。
9. 最终只交付已接受首帧、逐段豆包提示词、状态与性能报告，不自动操作豆包。

## 非目标

- 不接入 ChatGPT 私有图片接口。
- 不把 Plus 订阅当作 OpenAI API 额度。
- 不在首版支持 macOS、Linux、CLI 或 TUI 的完整审批展示。
- 不托管、发布或自动更新个人 skill。
- 不训练或微调图片模型。
- 不生成豆包视频、音频、字幕、音乐或最终剪辑。
