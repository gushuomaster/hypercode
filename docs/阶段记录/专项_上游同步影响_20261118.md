这一节按《上游同步工作流总纲》的"宿主对等清单"要求编写。首轮验证没有做这一步，是维护者在验收前指出的。

| `a97622c801` #49016 | 远端配置要求重新登录时给出明确提示 | **已补齐**（`CROSS_HOST_CONTRACT_ADAPTED`），见下文 |
| `29f07e0c69` #51414 | CLI 与 TUI 共用浏览器打开逻辑 | `host_only`：扩展使用 VS Code 自带的 `openExternal` |
| `055d95bb7e` #53852 | 为 C++ 模块接口文件（`.cppm`、`.ixx` 等）提供高亮 | 结果未变差，但存在既有差距，见下文 |

**已补齐的两项：**

1. **插件列表**
   - **原状**：扩展的系统状态面板原本没有插件区块，属于同步之前就存在的差异。
   - **改法**：插件名解析从 TUI 移到 `packages/product`（`deriveProductPlugins`）。只做字符串处理，同时识别 `/` 和 `\`，webview 中也能用。TUI 改为调用它；扩展在系统状态里列出插件和版本，没有插件时显示"没有插件"。
2. **远端配置认证失败**
   - **原状**：服务端返回 `ConfigRemoteAuthError`（HTTP 400）时，扩展面板只显示"未找到此工作区的会话元数据"。
   - **改法**：Product 新增错误语义 `error.config.remote_auth`。扩展面板改为显示中文的重新登录说明，并给出 `hypercode auth login <url>`。
   - **品牌修正**：upstream 这次在 TUI 中新增的提示（包括 upstream 测试的断言）写的是 `opencode auth login`，属于品牌残留，`rebrand:check` 没有拦下，现已改为 `hypercode`。

**既有差距（记录在案，建议另行立项）：**

- **代码高亮**：TUI 用一张完整的"扩展名 → 语言"映射表。扩展的 `CodeBlock.tsx` 和 `DiffBlock.tsx` 各有一份只含 10 种扩展名的映射，其余（包括 `.cpp`、`.py`、`.go`）靠 highlight.js 自动识别。C++ 模块文件在扩展中与普通 `.cpp` 一样走自动识别，结果没有因本次同步变差。
- **启动阶段配置错误的语言**：CLI 与 TUI 在启动阶段输出的配置类错误（JSON 格式、配置无效、远端认证等）仍是英文，属于本地化欠账。

**测试与变异验证：**
- product 新增插件解析测试与错误分类断言，扩展新增状态面板和远端认证的测试，TUI 上游测试改为断言 `hypercode`。
- 变异验证共三项，都被测试拦下：
  - 把 TUI 提示的品牌改回 `opencode`；
  - 让 Product 不再识别该错误；
  - 让插件解析只按 `\` 切分。
