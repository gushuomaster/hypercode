# HyperCode 品牌化报告

> 记录类型：阶段汇报  
> 记录用途：总结品牌化阶段已完成事项、保留项与后续风险。  
> 阅读时机：需要快速回看品牌化阶段做了什么、保留了什么、还遗留了什么时。  
> 文档边界：本文是阶段结果总结，不承担长期规范定义，也不承担逐次同步取证职责。

## 目标

将用户可见的 OpenCode 界面品牌化为 HyperCode,同时保留上游同步能力以及对兼容性敏感的内部实现。

## 本次完成的工作

- 建立了干净的 git 基线,并完成了仓库范围的品牌审计。
- 新增 [基线_品牌化审计](基线_品牌化审计.md)。
- 将选定的用户可见英文界面品牌化为 `HyperCode`:
  - 根目录 `README.md`
  - CLI 帮助/错误展示
  - VS Code 扩展显示元数据
  - 英文应用与桌面 UI 文案
- 新增主 `hypercode` CLI bin,同时保留 `opencode`。
- 新增以下兼容性支持:
  - `HYPERCODE_*` 环境变量,并以 `OPENCODE_*` 作为回退
  - `hypercode.json` / `hypercode.jsonc`
  - `.hypercode/` 与 `.opencode/` 并存
- 新增自动化脚本:
  - `scripts/rebrand-opencode-to-hypercode.mjs`
  - `scripts/sync-opencode-upstream.ps1`

## 保留的 OpenCode 引用及其原因

- `@opencode-ai/*` 包名与导入路径:
  - 为构建兼容性与上游同步安全而保留
- `packages/opencode` 目录及内部 `@opencode/...` 服务标识符:
  - 为避免侵入式重构而保留
- license、署名以及上游 GitHub URL:
  - 有意保留
- 本地化的非英文 UI 字符串:
  - 本次尚未完全品牌化
- 现有的 `.opencode` 与 `OPENCODE_*` 用法:
  - 作为兼容性回退保留

## CLI 状态

- `hypercode` bin:已新增
- `opencode` bin:已保留
- CLI 帮助展示:已切换为 `hypercode`

## 配置状态

- 新支持的名称:
  - `HYPERCODE_*`
  - `hypercode.json`
  - `hypercode.jsonc`
  - `.hypercode/`
- 保留的旧回退名称:
  - `OPENCODE_*`
  - `opencode.json`
  - `opencode.jsonc`
  - `.opencode/`

## 脚本

- 品牌化检查:
  - `node scripts/rebrand-opencode-to-hypercode.mjs --dry-run`
- 品牌化写入:
  - `node scripts/rebrand-opencode-to-hypercode.mjs --write`
- 上游同步 dry-run:
  - `powershell -File scripts/sync-opencode-upstream.ps1`
- 上游同步写入:
  - `powershell -File scripts/sync-opencode-upstream.ps1 -Write`

## 风险与后续工作

- 构建/测试验证目前因环境配置受阻:
  - `bun install` 在 `electron` postinstall 阶段因 `ECONNRESET` 失败
  - 因此 `packages/opencode` 验证仍缺少一次成功的 `bun typecheck` 与 CLI 运行时检查
- 快照与本地化覆盖仍需更大范围的处理。
- 缓存/数据/状态目录迁移尚未迁移到带回退的新 HyperCode 根目录。
- 安装/更新 URL 与包名仍指向 OpenCode 基础设施,应仅在 HyperCode 分发端点就绪后再更改。
