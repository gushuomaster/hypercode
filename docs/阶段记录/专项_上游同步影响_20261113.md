## 2. 方法与基线

- 同步基线：`193de13a88d62a6409c6d385831180f1def527dc`（`fix(stats): normalize deepseek v4.1 flash`，2026-09-10）。它不是 tag 提交，是 v1.18.30 发布后 upstream `dev` 上的提交；`v1.19.5`、`v2.2.7` 与 `upstream/dev` 都以它为祖先，与 HyperCode 的 merge-base 也都是它。
- HyperCode 一侧：本轮暂存改动的快照（`git write-tree` + `git commit-tree` 生成的临时提交 `cc7b3f505d`，未移动任何分支），即提交后的预期状态。
- upstream：`git remote add upstream https://github.com/anomalyco/opencode.git` 后 `git fetch upstream --tags`。
- 冲突清单：`git merge-tree --write-tree --name-only` 在内存中试合并，不改工作区与分支，得到的是真实冲突，而不是"双方都改过"的估计。
- 三组 diff 口径：A = upstream 基线→目标；B = 基线→HyperCode；C = A∩B（双方都改过的文件）。

## 5. 需要维护者决策

### 5.1 更新检查与 OpenCode 2.0 推销（同步 v1.19.5 前必须定案）

现状：HyperCode 的 `cli/upgrade.ts` 沿用 upstream 旧逻辑，不配置 `autoupdate` 时会检查并自动安装 patch 更新，更新源是 upstream 发布渠道。Windows 离线包安装时设置 `HYPERCODE_DISABLE_AUTOUPDATE=1`，Linux 离线模板未设置（需求盘点 D3，`2026-09-24-product-default-audit.md` 归为 `PROFILE_SPECIFIC_DEFAULT`）。

v1.19.5 合入后，如不处理，未设置该变量的 HyperCode 会联网检查 upstream 版本，并在 TUI 中提示用户安装 OpenCode 2.0。

建议：`PRESERVE_HYPERCODE_DEFAULT`——HyperCode 目前没有自己的更新渠道，交付版默认关闭更新检查（不论 `autoupdate` 是否配置），`/update` 命令与更新提示不对用户开放；Product 命令目录把 `opencode.update` 声明为 `host_only` 并在 HyperCode 中不注册，或由 Product 统一标记为 unsupported。Linux 离线模板同步补上 `HYPERCODE_DISABLE_AUTOUPDATE=1` 作为双保险。

### 5.2 2.x 的长期路线

1.x 维护线还在发版，但 upstream 主要开发已在 2.x。继续跟 1.x 的成本低，但迟早要迁移。建议在 v1.19.5 同步完成后单独开一个"2.x 迁移评估"change：盘点 HyperCode 能力在 2.x 新架构中的挂载点（品牌别名、配置引导、CLI 入口与授权门禁、OpenAPI 品牌边界、TUI 本地化、Product 契约），估算 fork tax 后再决定。
