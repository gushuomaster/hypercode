# HyperCode 安装部署说明

## 1. 这份文档适合谁

本文面向收到 HyperCode 交付包的客户用户和现场管理员，重点回答四个问题：

- 客户机器上需要安装什么
- License 应该如何放置和验证
- 默认模型与配置是否需要手工设置
- 安装完成后如何验收是否可用

如果你已经安装完成，只想了解日常如何使用，请阅读 [使用说明书](使用说明书.md)。

## 2. 交付物清单

一个标准 Windows 交付包通常至少包含以下内容：

- `hypercode.exe`
- `hypercode.vsix`
- 现场提供的 License 字符串或 License 发放流程
- 如有定制，还可能包含项目级配置、扩展能力或补充说明

普通客户用户最常接触的是前两项：

- `hypercode.exe`：命令行入口
- `hypercode.vsix`：VS Code 扩展安装包

## 3. 安装前准备

开始前建议确认以下条件：

- 客户机器可以正常运行 Windows PowerShell
- 已安装 VS Code
- 有可读写的用户目录
- 如果交付版连接在线模型服务，客户网络可以访问现场指定的模型服务地址

说明：

- 新版 HyperCode 在 Windows 上获取机器码时不依赖必须安装 `wmic`
- 即使目标机没有 `wmic`，只要 PowerShell 可用，仍然可以正常获取机器码和校验 License

## 4. 5 分钟快速安装

如果你想先跑通主路径，可以直接按下面顺序操作。

### 4.1 安装 CLI

把 `hypercode.exe` 放到客户机器上的固定目录，例如：

```powershell
C:\tools\hypercode\hypercode.exe
```

建议二选一：

- 直接在该目录中运行
- 或把该目录加入 `PATH`，后续可以在任意终端直接执行 `hypercode`

验证方式：

```powershell
hypercode --version
```

如果能输出版本号，说明 CLI 已可执行。

### 4.2 安装 VS Code 扩展

在 VS Code 中执行：

1. 打开命令面板
2. 输入 `Extensions: Install from VSIX...`
3. 选择 `hypercode.vsix`
4. 安装完成后按提示重载 VS Code

安装完成后，你应该可以在活动栏中看到 `HyperCode`。

### 4.3 写入 License

Windows 默认 License 路径为：

```text
C:\hyper-aicode\license.txt
```

把管理员提供的 License 字符串完整写入这个文件。

如果目录不存在，先创建：

```powershell
mkdir C:\hyper-aicode
notepad C:\hyper-aicode\license.txt
```

说明：

- CLI 和 VS Code 扩展共用同一个 License 文件
- `license.txt` 中应只保留最终 License 字符串，不要额外添加说明文字

### 4.4 启动一次 HyperCode

第一次启动时执行：

```powershell
hypercode
```

当前交付版通常会在首次启动时自动维护全局配置目录下的基础配置文件，无需客户手工创建基础 provider 配置。

Windows 全局配置目录通常位于：

```text
%USERPROFILE%\.config\opencode\
```

## 5. License 申请与验证

如果客户现场还没有拿到 License，可以按下面流程处理。

### 5.1 在目标机上获取机器码

在目标机终端执行：

```powershell
hypercode license machine-id
```

把输出结果发给管理员或发证机。

说明：

- 这是目标机的机器码
- 生成 License 时必须使用目标机自己的机器码
- 新版交付版即使缺少 `wmic`，通常也能通过 PowerShell 获取机器码

### 5.2 把 License 写回目标机

管理员生成 License 后，把最终字符串写入：

```text
C:\hyper-aicode\license.txt
```

### 5.3 验证 License 是否生效

执行：

```powershell
hypercode license status
```

如果返回类似“license is valid”，说明当前机器 License 正常。

你也可以随时查看程序认定的 License 路径：

```powershell
hypercode license path
```

## 6. 默认模型与配置说明

### 6.1 客户通常不需要手工连接 provider

当前交付版默认会带一套预置配置，常见默认模型为：

```text
minimax-direct/MiniMax-M2.7
```

对客户来说，这意味着：

- 一般不需要自己手工创建基础 provider 配置
- 一般不需要自己去连接模型服务商
- 正常情况下，启动后就会使用交付版预置的默认模型

### 6.2 全局配置文件会自动维护

当前 CLI 会在全局配置目录下维护：

```text
%USERPROFILE%\.config\opencode\opencode.json
```

在默认交付模式下：

- 如果这个文件不存在，程序会自动创建
- 如果这个文件内容与交付版内置默认配置不一致，程序会自动覆盖

这一步的目的，是保证客户机器上的默认 provider / model 与交付版保持一致。

因此建议：

- 普通客户用户不要手工修改自动维护的 `opencode.json`
- 如果现场要做定制，请由管理员统一调整

### 6.3 还有哪些配置文件会被读取

除了自动维护的 `opencode.json`，程序还会兼容读取下列文件：

- `%USERPROFILE%\.config\opencode\hypercode.json`
- `%USERPROFILE%\.config\opencode\hypercode.jsonc`
- 项目根目录下的 `hypercode.json`
- 项目根目录下的 `opencode.json`

如果现场需要做额外覆盖，通常建议由管理员在这些定制配置里处理，而不是让普通用户手改自动维护文件。

## 7. 安装后验收

建议至少做下面 5 项验收。

### 7.1 验证 CLI 可执行

```powershell
hypercode --version
```

### 7.2 验证 License 正常

```powershell
hypercode license status
```

### 7.3 验证当前实际配置

```powershell
hypercode debug config
```

重点查看：

- 当前是否已经解析到预期的 `model`
- 当前是否已经解析到预期的 `provider`

### 7.4 验证模型列表可见

```powershell
hypercode models minimax-direct
```

如果是标准 MiniMax 直连交付版，通常应该能看到类似：

- `minimax-direct/MiniMax-M2.7`
- `minimax-direct/MiniMax-M2.7-highspeed`

### 7.5 验证一次最小调用

```powershell
hypercode run -m minimax-direct/MiniMax-M2.7 "回复ok"
```

如果模型可用，通常会返回一条简短结果。

说明：

- 模型名区分大小写，建议直接使用 `hypercode models minimax-direct` 查到的完整名称
- 如果这里失败，但 `models` 能看到模型，通常说明是上游服务、鉴权或网络问题，而不是本地安装问题

### 7.6 验证 VS Code 扩展

在 VS Code 中执行：

- 打开 `HyperCode`
- 运行 `HyperCode: Check Environment`
- 尝试 `HyperCode: New Session`
- 尝试 `HyperCode: Ask About Current File`

如果这些入口都能正常打开，说明扩展侧主路径已打通。

## 8. 常见安装问题

### 8.1 启动时报 `spawn wmic ENOENT`

这通常说明客户机器没有 `wmic`，而使用的还是旧版 CLI 或旧版扩展逻辑。

处理建议：

- 优先更换为新版交付版
- 新版会在 Windows 上优先尝试兼容获取机器码，不要求单独安装 `wmic`
- 如果新版仍失败，确认 PowerShell 可正常运行

### 8.2 License 已写入，但启动仍提示授权异常

按下面顺序检查：

1. 执行 `hypercode license path`，确认写入位置是否正确
2. 执行 `hypercode license status`，确认是否返回 valid
3. 如果提示 invalid，重新在目标机执行 `hypercode license machine-id`
4. 用新的机器码重新生成并写入 License

常见原因：

- 写错了机器的 License
- `license.txt` 中多了空格、换行或说明文字
- 目标机更换了硬件或镜像环境

### 8.3 `debug config` 已有 MiniMax 配置，但界面中看不到预期模型

先分开判断：

- 如果 `hypercode models minimax-direct` 能看到模型，说明配置已经被 CLI 识别
- 如果 CLI 能看到但界面没显示，优先检查扩展界面刷新、当前会话状态或交付版本差异

建议先执行：

```powershell
hypercode debug config
hypercode models minimax-direct
```

把结果交给管理员继续排查。

### 8.4 `hypercode run -m ...` 调用失败

先核对三件事：

- 模型名称是否和 `hypercode models` 输出完全一致
- 当前网络是否可访问现场指定的模型服务
- 当前 API Key / provider 配置是否仍有效

如果模型列表能显示，但调用返回上游服务错误，通常需要联系管理员检查 provider 端。

### 8.5 VS Code 里看不到 HyperCode 入口

建议按顺序检查：

1. `hypercode.vsix` 是否安装成功
2. VS Code 是否已重载
3. CLI 是否可以正常执行
4. 执行 `HyperCode: Check Environment`

## 9. 现场管理员补充建议

如果你是现场管理员，推荐这样交付给客户：

- 把 `hypercode.exe` 和 `hypercode.vsix` 一起交付
- 先在目标机上取机器码，再生成最终 License
- 先完成 `license status`、`debug config`、`models` 三项验收
- 只有在需要现场定制时，才额外下发覆盖配置

对普通客户用户来说，最理想的交付结果应该是：

- 安装 CLI
- 安装 VSIX
- 写入 License
- 直接开始使用

也就是说，客户通常不需要自己理解 provider 内部细节，就可以正常进入 HyperCode。
