# OpenCode 与 HyperCode 功能总览

本文只回答两个问题：

- OpenCode 和 HyperCode 现在共同具备哪些功能特色
- HyperCode 在当前交付版本里额外提供了哪些、用户可以直接看到或使用到的功能特色

本文依据当前仓库中的 `README.zh.md`、用户指南、VS Code 扩展说明和扩展清单整理，只描述当前可见、可验证、可使用的能力。

## 1. OpenCode 与 HyperCode 共有的功能特色

### 1.1 以会话为中心推进开发任务

两者当前都以“会话”作为主要工作方式。用户可以在一个连续上下文里提问、补充要求、继续修改，而不是每次只执行一条独立命令。

从用户角度看，这意味着你可以：

- 连续追问同一个问题，而不必每次重新解释上下文
- 继续上一次未完成的任务
- 按会话记录回看历史内容

在当前文档里，对应入口包括 `run --continue`、`run --session <session-id>`、`session list` 等。

### 1.2 内置多种 Agent 协作方式

两者当前都支持多种 Agent 工作模式，用来适配不同类型的开发任务。

用户可以直接使用或感知到的能力包括：

- `build`：适合直接推进开发、修改和执行任务
- `plan`：适合先分析代码、梳理方案和确认思路
- `@general`：适合复杂搜索、多步整理和辅助处理

在实际使用时，用户通常不需要理解内部实现，只需要知道可以按任务类型选择不同工作方式。

### 1.3 支持多种入口协作

两者当前都不只提供单一入口，而是支持在不同工作环境中协作。

用户可以从这些入口使用：

- CLI / TUI：适合在终端里直接发起任务、连续对话和查看结果
- VS Code：适合在编辑器里结合代码上下文协作
- 相关桌面或 Web 形态：当前仓库中可以看到对应工作区和产品结构

这让用户可以根据自己的工作习惯，在终端和编辑器之间切换，而不需要改变核心使用方式。

### 1.4 覆盖常见开发任务

两者当前共同具备的核心价值，是围绕日常开发工作提供连续支持，而不只是回答问题。

用户现在可以用它们做的常见事情包括：

- 阅读和解释代码、模块关系、调用链和项目结构
- 分析报错、配置异常、权限问题和接口行为
- 在要求明确后修改代码、文档和配置
- 帮助拆解复杂任务、整理执行步骤、补充测试思路
- 查看当前模型、Provider 和生效配置

这些能力在 `run`、`models`、`debug config` 以及会话过程中的任务拆解里都能体现出来。

### 1.5 支持会话内命令、历史恢复和扩展能力

两者当前都支持在会话内部继续操作，而不是退出后重新开始。

用户可直接使用的会话命令包括：

- `/new`
- `/compact`
- `/model`
- `/theme`
- `/sessions`
- `/undo`
- `/refresh`
- `/skills`
- `/redo`
- `/reset-agent`

同时，用户在实际使用中也可能看到或用到这些扩展能力：

- MCP 服务接入
- 自定义 commands、agents、tools、plugins
- Todo、Subagents、技能调用等任务拆分机制
- 多模型切换和主题配置

对普通用户来说，这些能力的意义是：同一个工具既能持续对话，也能接入更多工作流能力，而不用换一套系统。

## 2. HyperCode 独有的功能特色

### 2.1 面向交付的独立使用入口

HyperCode 在当前交付版本中，把用户入口明确收口为两个主要文件：

- `hypercode.exe`
- `hypercode.vsix`

这意味着用户拿到交付包后，通常不需要自己理解完整源码结构，只需要围绕这两个入口完成安装和使用：

- 用 `hypercode.exe` 在 Windows 命令行中运行
- 用 `hypercode.vsix` 在 VS Code 中安装扩展

这比“从源码环境自行拼装运行入口”更接近实际交付场景。

### 2.2 VS Code 工作区级集成界面

HyperCode 当前最明显的独有特色，是在 VS Code 中提供了完整的工作区级集成，而不是只打开一个终端。

用户现在可以直接看到或使用：

- Activity Bar 中的 `HyperCode` 入口
- Secondary Sidebar 中的辅助区域
- `Sessions`、`Todo`、`Modified Files`、`Subagents`、`Session` 等视图
- 快速新建会话、搜索会话、归档、分享、按标签筛选、打开工作区浏览器、环境检查等命令

这些能力来自当前扩展清单，说明 HyperCode 在编辑器里提供的是一个会话工作台，而不只是命令行的壳层。

### 2.3 工作区级 Runtime 闭环

根据当前 VS Code 扩展说明，HyperCode 会为它管理的每个工作区启动一次 `hypercode serve`。

从用户角度看，这带来的直接体验是：

- 每个工作区有相对独立的会话运行环境
- 可以在编辑器侧边栏持续查看当前工作区的会话和任务状态
- 可以在同一工作区里继续查看会话正文、Todo、Subagents 和修改结果

这让 HyperCode 更适合长时间、多轮次的编辑器内协作。

### 2.4 可直接使用的授权能力

HyperCode 当前交付版提供了明确的授权使用流程，用户可以直接执行相关命令完成检查和排查。

当前文档中可见的授权入口包括：

- `hypercode license machine-id`
- `hypercode license status`
- `hypercode license path`

对应的用户价值是：

- 可以查看当前机器标识，用于申请授权
- 可以检查授权是否有效
- 可以确认授权文件应放置的位置

这类授权命令是当前 HyperCode 交付路径中的直接组成部分，普通用户可以实际操作。

### 2.5 面向交付环境的默认模型与配置维护

HyperCode 当前还提供了更偏交付环境的默认配置体验，减少用户首次使用时的准备成本。

用户可以从现有说明里直接看到这些特征：

- 默认模型约定为 `minimax-direct/MiniMax-M2.7`
- 首次启动会自动维护全局配置文件
- 除默认配置文件外，还兼容读取 `hypercode.json`、`hypercode.jsonc` 和项目根目录配置

对用户来说，这表示：

- 首次安装后更容易直接开始使用
- 管理员可以按交付环境预置默认模型
- 用户在常见配置路径下更容易接入项目配置

如果需要进一步查看安装步骤、授权处理和实际命令示例，可继续阅读 [安装部署说明](安装部署说明.md) 和 [使用说明书](使用说明书.md)。
