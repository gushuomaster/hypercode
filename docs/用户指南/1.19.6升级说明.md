# HyperCode 升级到 OpenCode 1.19.6：用户能感受到的变化

本次 HyperCode 的上游基线从 OpenCode 1.18.30 同步到 OpenCode 1.19.6（OpenCode 1.x 维护线）。原有的配置文件、模型配置、License 和会话记录都可以继续使用。

本文只回答一个问题：升级之后，你在终端和 VS Code 里**能直接看到、直接用上**的变化有哪些。内部实现、代码结构这类内容不在本文范围内。

## 一、先说结论

- 本次以缺陷修复为主，新增能力不多。
- **会话分享功能已停用**：上游 OpenCode 已停止会话分享服务，HyperCode 随之在终端与 VS Code 两端同时下线分享入口。详见第二节。
- **HyperCode 没有在线更新渠道**：上游 1.19 新增的 `/update` 更新对话框、启动时的更新提示，以及引导安装 OpenCode 2 的内容，在 HyperCode 中都不会出现。升级请向管理员获取新的安装包。详见第三节。
- CLI、VS Code 扩展和 Ubuntu 离线包的版本号统一为 `1.19.6`。

## 二、会话分享已停用

上游 OpenCode 在 1.19 停止了会话分享服务，分享链接已无法生成，也无法打开。HyperCode 的处理如下：

| 位置 | 变化 |
| --- | --- |
| TUI | 命令面板中不再有“分享会话”“取消分享会话”，`/share`、`/unshare` 不再可用；侧栏不再显示分享链接；首页提示中不再出现分享相关内容 |
| VS Code 扩展 | 会话列表右键菜单与命令面板中不再提供分享、取消分享 |
| `hypercode run --share` | 参数仍可写，但不再生效，也不再出现在帮助中 |
| `hypercode import <分享链接>` | 不再支持从分享链接导入，会提示“不再支持从分享 URL 导入：会话分享功能已停用”。从 `hypercode export` 导出的 JSON 文件导入不受影响 |

已有会话的内容不受影响，仍然保存在本机。需要把会话交给他人时，请用 `hypercode export` 导出 JSON 文件，对方再用 `hypercode import` 导入。

## 三、版本更新方式

HyperCode 由管理员统一分发安装包，没有在线更新渠道：

- 启动 TUI 时不会联网检查新版本，也不会弹出更新提示。
- TUI 中没有 `/update` 命令。
- `hypercode upgrade` 不再出现在帮助中；如果执行，会提示“HyperCode 没有在线更新渠道，请向管理员获取新的安装包。”并以非零退出码结束，不会从上游下载任何内容。

升级方式不变：按《安装部署说明》或《Ubuntu 20.04 离线安装与配置》替换可执行文件、离线包和 `hypercode.vsix`。

## 四、模型与供应商

- **自定义推理强度**：在模型配置中写 `reasoning_options`，HyperCode 会按其中列出的取值生成可选的推理强度（variants），并替换模型目录中自带的同类选项；写空数组 `[]` 表示该模型不提供推理强度选项。原有的 `variants` 配置仍可在此基础上补充参数。

  ```json
  {
    "provider": {
      "anthropic": {
        "models": {
          "claude-sonnet-4-6": {
            "reasoning_options": [{ "type": "effort", "values": ["low", "high"] }]
          }
        }
      }
    }
  }
  ```

- **历史图片不再无限重发**：长会话中累计重发的历史图片超过约 25 MiB 时，较早的图片会从请求中移除（只影响发给模型的请求，本地会话记录不变），避免请求过大导致失败。被移除的图片需要时可以重新附加。
- Gemini：思考（thinking）参数的默认取值逻辑调整，减少因参数不受支持而报错的情况。
- Cloudflare AI Gateway：供应商上配置的超时设置现在对网关模型同样生效。
- OpenAI：支持 `ultrafast` 服务等级；Codex 登录方式可使用 GPT-6 Sol 与 GPT-6 Luna。
- xAI：工具返回的图片可以正常传给模型。
- Amazon Bedrock：工具返回图片的处理方式按模型区分，减少不支持图片的模型报错。

## 五、命令行与终端界面

- **`hypercode debug config` 自动隐藏敏感信息**：输出中名称类似 `apiKey`、`secret`、`password`、`token`、`authorization`、`cookie`、`credential`、`privateKey` 的字段，`headers` 中的所有值，以及带用户名、密码或敏感查询参数的 URL，都显示为 `***`。这只影响 `debug config` 的显示，实际生效的配置不变，可以放心把输出贴给维护者排查问题。
- 连接远程服务端时，如果启动阶段认证失败，TUI 会显示具体的错误原因。
- `/status` 中插件名称在 Windows 上显示正确。
- 代码高亮支持 C++ 模块接口文件。

## 六、VS Code 扩展

- 扩展版本为 `1.19.6`，对应安装包为 `hypercode.vsix`。安装本地 VSIX 后，可以在扩展详情页确认版本号。
- 会话分享入口已下线，见第二节。其余功能与语言设置不变。

## 七、怎么确认自己已经升级

```bash
hypercode --version
```

输出 `1.19.6` 即为本版本。

## 说明

- 本文整理的是上游 OpenCode 1.18.30 → 1.19.6 区间内、普通用户可感知的变化。
- 上游同期发布的 OpenCode 2.x 是另一条产品线，HyperCode 本次未同步。
- 上游在同一区间还有面向 Web、桌面等形态的改动（包括桌面版的 OpenCode 2 升级引导），这些产物不在 HyperCode 当前交付面（`hypercode.exe`、Ubuntu 离线包与 `hypercode.vsix`）内，因此未列入本文。
- 想了解 OpenCode 与 HyperCode 的整体能力对照，请看 [OpenCode 与 HyperCode 功能总览](OpenCode与HyperCode功能总览.md)。
