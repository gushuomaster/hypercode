# HyperCode 使用说明书

## 1. 这份文档适合谁

本文面向已经完成安装的客户用户，重点回答三个问题：

- 从哪里进入 HyperCode
- 进入以后每个界面和命令是做什么的
- 日常应该怎么提问、怎么协作、怎么继续历史会话

如果你还没有完成安装、License 写入或首次可用性验证，请先阅读 [安装部署说明](安装部署说明.md)。

## 2. 3 分钟快速开始

### 2.1 在 CLI 中开始

进入你的项目目录后执行：

```powershell
cd D:\work\your-project
hypercode
```

进入会话后，建议第一次先这样提问：

- `先读一下这个项目，告诉我它是做什么的`
- `解释当前目录的核心模块，不要修改文件`
- `先给我一个阅读顺序，再逐步展开`

如果你已经有非常明确的目标，也可以直接一条命令启动：

```powershell
hypercode run "阅读这个仓库并总结启动流程"
```

### 2.2 在 VS Code 中开始

安装扩展后，推荐通过以下任一入口进入：

- 活动栏中的 `HyperCode`
- 命令面板中的 `HyperCode: New Session`
- 命令面板中的 `HyperCode: Quick New Session`

如果你想围绕当前代码直接提问，优先使用：

- `HyperCode: Ask About Current File`
- `HyperCode: Ask About Selection`
- `HyperCode: Ask About Selected Files`

这几种入口会把当前文件、选中文本或选中的文件列表一并带入上下文，通常比手工复制代码更高效。

## 3. HyperCode 可以帮助你做什么

HyperCode 是面向开发工作的智能协作工具。日常最常见的用途包括：

- 阅读和解释代码
- 定位报错、调用链或配置问题
- 评估某个修改会影响哪些模块
- 按要求修改文件
- 补充测试、文档和说明
- 把一个较大的目标拆成若干可执行步骤

推荐把它理解成“会读项目、会分析问题、会按要求执行改动的开发协作助手”，而不只是一个普通聊天窗口。

## 4. 从哪里进入 HyperCode

### 4.1 CLI 入口

CLI 适合以下场景：

- 需要快速分析整个仓库
- 需要在终端里连续推进一个长任务
- 需要继续之前的历史会话
- 需要做环境检查、查看模型或验证配置

常用命令：

```powershell
hypercode
hypercode run "你的任务"
hypercode session list
hypercode run --continue
hypercode run --session <session-id>
```

这些命令的含义见后文“终端命令说明”。

### 4.2 VS Code 入口

VS Code 适合以下场景：

- 围绕当前文件、当前选区直接提问
- 边看代码边和 HyperCode 协作
- 需要查看待办、改动文件和子任务视图
- 需要在编辑器里复核会话结果

Windows / Linux 默认快捷键：

- `Ctrl+Esc`：`HyperCode: Quick New Session`
- `Ctrl+Shift+Esc`：`HyperCode: New Session`
- `Ctrl+Alt+K`：`HyperCode: Ask About Current File`

## 5. 第一次推荐怎么用

如果你第一次接触一个项目，建议使用下面这套顺序：

1. 先让 HyperCode 解释现状
2. 再让 HyperCode 说明问题原因或方案
3. 最后再让 HyperCode 执行改动

推荐提示语：

- `先解释这个项目的主入口，不要改文件`
- `把这个问题拆成 3 步处理`
- `先分析风险，确认后再修改`
- `只看当前文件，不要扩展到整个仓库`

这样通常比一上来就说“直接改”更稳定，也更方便你控制范围。

## 6. 会话界面怎么看

无论是在 CLI 还是 VS Code 中，HyperCode 的核心都是“会话”。

一个标准会话通常包含这些部分：

- 历史消息区：显示你之前的提问、系统的分析、执行过程和结果
- 输入区：你继续输入要求的地方
- 自动补全区：输入 `/`、`@` 或文件路径时弹出的选择列表
- 状态信息：有时你会看到任务拆解、技能调用、子任务处理等执行痕迹

如果你在执行过程中看到“Todo”“Subagents”“技能调用”之类的内容，通常表示系统正在把复杂任务拆开处理，这属于正常现象，不代表报错。

## 7. VS Code 侧边栏视图说明

VS Code 扩展安装完成后，左侧通常可以看到一个 `HyperCode` 视图容器。常见视图如下：

### 7.1 Sessions

`Sessions` 用来查看当前工作区下的会话列表。你可以把它理解为“这个项目的会话目录”。

适合做的事情：

- 打开历史会话
- 新建会话
- 在多个会话之间切换
- 按名称回忆上次工作内容

部分交付版本还会在这里提供重命名、归档、标签筛选或分享相关操作。

### 7.2 Todo

`Todo` 展示当前任务被拆成了哪些待办项。

适合做的事情：

- 判断 HyperCode 是否理解了你的目标
- 观察当前任务推进到哪一步
- 在复杂任务中快速掌握整体进度

### 7.3 Modified Files

`Modified Files` 展示当前会话已经改动过的文件。

适合做的事情：

- 快速复核改动范围
- 判断这次任务是否改到了你关心的文件
- 结合 Git 或编辑器 diff 检查结果

### 7.4 Subagents

`Subagents` 展示系统拆出去并行处理的小任务。

适合做的事情：

- 了解复杂任务为什么会分成多步
- 理解系统当前在并行做哪些事情

普通客户用户通常不需要单独操作它，但在查看复杂任务过程时很有帮助。

### 7.5 Session

`Session` 是主会话视图，核心交互都在这里进行。

适合做的事情：

- 阅读回答
- 继续提问
- 输入 `/` 命令
- 切换模型、主题、技能或会话

## 8. 会话内命令说明

在输入框里输入 `/`，会看到会话内命令列表。它们和终端命令不同，主要用于当前会话内部操作。

### 8.1 内置会话命令

- `/new`
  立即在当前工作区开启一个新会话。

- `/compact`
  用当前模型总结并压缩本次会话，适合会话很长时整理上下文。

- `/model`
  打开当前会话的模型选择器，用于切换本次会话使用的模型。

- `/theme`
  打开会话面板主题选择器，只影响显示风格，不影响模型能力。

- `/sessions`
  打开当前工作区的会话选择器，便于切换到别的历史会话。

- `/undo`
  撤销上一轮用户消息对应的动作，适合刚刚输入错内容时回退。

- `/refresh`
  重新加载当前会话快照，适合界面状态没有及时刷新的情况。

- `/skills`
  打开技能选择器，并把选中的技能命令插入当前输入框。

- `/redo`
  如果当前会话存在可恢复的撤销记录，会显示这个命令，用于恢复刚才撤销的内容。

- `/reset-agent`
  如果当前输入框临时切到了别的 agent，这个命令可以恢复为默认 agent。

### 8.2 内置工作命令

除了上面的会话控制命令，`/` 列表里通常还会出现一些工作命令。当前内置的基础命令包括：

- `/init`
  用于引导创建或更新 `AGENTS.md` 这类协作说明文件。

- `/review`
  用于审查当前变更，也可以针对指定 `commit`、`branch` 或 `pr` 做 review。

如果管理员在交付环境里增加了 MCP 命令、自定义命令或额外技能，它们也可能出现在 `/` 自动补全列表中。

## 9. 终端命令说明

下面这些是客户最常用的 CLI 命令。

### 9.1 启动和执行

```powershell
hypercode
```

启动交互式会话。适合你希望边看边问、连续推进任务的时候使用。

```powershell
hypercode run "解释这个仓库的核心模块"
```

直接带着任务启动一次会话。适合快速发起一个明确问题。

### 9.2 会话管理

```powershell
hypercode session list
```

列出历史会话，适合找回之前处理过的任务。

```powershell
hypercode run --continue
```

继续最近一次会话。

```powershell
hypercode run --session <session-id>
```

继续指定编号的历史会话。

### 9.3 环境和配置检查

```powershell
hypercode --help
hypercode --version
hypercode debug config
```

- `--help`：查看命令帮助
- `--version`：查看当前 CLI 版本
- `debug config`：查看当前实际生效的配置，适合排查 provider、model、plugin 或 MCP 配置问题

### 9.4 模型和授权检查

```powershell
hypercode models
hypercode models minimax-direct
hypercode license status
hypercode license path
```

- `models`：查看当前可用模型列表
- `models minimax-direct`：只查看 `minimax-direct` provider 下的模型
- `license status`：检查当前机器上的 License 是否有效
- `license path`：输出当前 License 文件应放置的位置

如果需要把目标机机器码发给管理员生成 License，还可以执行：

```powershell
hypercode license machine-id
```

## 10. HyperCode 的内置能力

交付版 HyperCode 一般已经内置了常用技能、任务拆解能力和辅助流程，客户通常不需要额外安装。

你可以把这些能力理解为：

- 代码理解：解释函数、模块、调用链和项目结构
- 任务规划：把一个需求拆成多个步骤
- 问题定位：围绕报错、配置、接口和权限寻找原因
- 改动执行：在要求明确后修改代码、文档或配置
- 影响分析：说明某次改动可能波及哪些位置
- 并行处理：把复杂任务拆成多个辅助子任务再汇总

当会话中出现技能调用、待办拆解或子任务执行时，通常是这些内置能力在工作。

## 11. 常见工作场景

### 11.1 看懂一个陌生项目

推荐这样开始：

- `先概览这个项目的目录结构`
- `告诉我主入口和启动流程`
- `给我一个建议的阅读顺序`

### 11.2 分析一个报错

推荐这样提问：

- `帮我定位这个报错可能来自哪里`
- `按调用链分析这个异常`
- `先说原因，不要修改文件`

### 11.3 围绕当前文件工作

在 VS Code 中最方便的做法是：

1. 打开当前文件
2. 运行 `HyperCode: Ask About Current File`
3. 直接继续追问细节

适合的问题：

- `解释这个文件在做什么`
- `指出这里最容易出错的地方`
- `如果要重构，建议先改哪一层`

### 11.4 让 HyperCode 改代码

建议把范围说清楚：

- `只改当前文件`
- `先给修改方案，我确认后再改`
- `补一个最小可用测试`

### 11.5 继续上次工作

如果你希望保留上下文，尽量继续原会话而不是新建会话。

常用方法：

```powershell
hypercode session list
hypercode run --continue
```

## 12. 常见问题

### 12.1 我只想让它分析，不想让它直接改

直接这样说即可：

- `先分析，不要改文件`
- `先给方案，确认后再执行`
- `只解释原因，不要动代码`

### 12.2 回答太宽泛

建议缩小范围：

- 指定文件、函数或模块
- 指定“只看当前目录”或“只看当前文件”
- 先问结构，再问细节

### 12.3 为什么会看到 Todo、Subagents 或技能调用

这通常不是异常，而是系统在拆解和执行复杂任务。可以把它理解成“系统正在分步处理”。

### 12.4 为什么模型选择器里没有看到预期模型

先执行下面两条命令核对环境：

```powershell
hypercode models
hypercode debug config
```

如果 `debug config` 里已经能看到预期 provider/model，但界面仍未显示，请联系管理员进一步检查交付版本或界面刷新状态。

### 12.5 想切换默认模型怎么办

普通客户用户通常不需要自行修改默认模型。交付版常见做法是由管理员统一下发默认 provider/model。

如果现场确实需要切换，请联系管理员统一调整全局配置或项目配置。

## 13. 推荐的使用习惯

最后给客户一个最实用的建议：把 HyperCode 当成一个“需要明确边界的协作同事”。

最有效的提问方式通常具备三个特点：

- 目标明确
- 范围明确
- 是否允许修改明确

例如：

- `解释这个模块的职责，不要改文件`
- `先分析登录失败原因，再给修复方案`
- `只修改当前文件，并补一个最小测试`

这样做，通常能得到最稳定、最符合预期的结果。
