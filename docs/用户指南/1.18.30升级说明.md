# HyperCode 升级到 OpenCode 1.18.30：用户能感受到的变化

本次 HyperCode 的上游基线从 OpenCode 1.17.3 同步到 OpenCode 1.18.30。这次升级没有破坏性变更，你原有的配置文件、命令用法和会话记录都可以继续使用。

本文只回答一个问题：升级之后，你在终端里**能直接看到、直接用上**的变化有哪些。内部实现、代码结构这类内容不在本文范围内。

## 一、先说结论

- 可感知的变化集中在**终端界面（TUI）**、**命令行参数**和 **VS Code 扩展双语界面**。
- VS Code 扩展版本同步为 `1.18.30`，扩展宿主、会话面板和侧栏现已支持简体中文与英文。
- 最值得留意的几项：出错提示页重做、Diff 支持对比主分支、新增调试信息面板、会话列表更好用、新增 `/skills` 与 `/debug`、Agent 可以读取 MCP 资源。

## 二、终端界面（TUI）

### 2.1 出错时的提示页重做

以前程序出错只会给你一行提示，外加一个“复制 issue 链接”的按钮。现在会打开整屏的错误页：

- 显示完整错误信息和调用堆栈，可以用方向键、PageUp / PageDown、Home / End 滚动查看
- 提供三个动作：`c` 复制报告（自动带上版本号、系统和终端信息，可直接贴给维护者）、`r` 重启、`q` 退出
- 支持鼠标点击，也支持左右方向键和 Tab 切换动作
- 终端窗口较矮时会自动隐藏次要内容，避免关键信息被截断

### 2.2 Diff 查看器可以对比主分支

打开 Diff 查看器后，切换数据来源的菜单里现在可能有三项：

- `Working tree`：当前工作区的改动
- `Main branch`：与默认分支的差异（只有当前分支不是默认分支时才会出现）
- `Last turn`：上一轮助手产生的改动

标题栏会直接标出你当前看的是哪一个来源。

### 2.3 新增“调试信息”面板

在输入框输入 `/debug` 可以打开调试信息面板，里面会列出：版本号与发布渠道、当前时间、操作系统、终端类型、当前会话 ID、当前模型。按回车即可整段复制，反馈问题时不用再自己收集环境信息。

### 2.4 会话列表更好用

- 打开会话列表时直接按最近使用加载，不再依赖当前会话缓存是否已经同步
- 输入搜索词会向服务端查询更多匹配结果（最多 30 条），并叠加本地过滤
- 删除会话后条目会立即从列表中消失，不会再残留到下一次刷新
- 当前正在使用的会话和已置顶的会话始终保留在列表里

### 2.5 新增 `/skills`，技能选择器更稳

在输入框输入 `/skills` 可以直接打开技能选择器。如果技能列表或者“切换组织”加载失败，对话框会显示具体的错误原因，而不是让整个界面出错。

### 2.6 光标外观可配置

`tui.json` 新增 `cursor` 配置段：

| 配置项 | 可选值 | 说明 |
| --- | --- | --- |
| `cursor.style` | `block`、`underline`、`line`、`default` | 光标形状，`default` 表示沿用终端自身设置 |
| `cursor.blinking` | `true` / `false` | 是否闪烁；`style` 为 `default` 时不生效 |

### 2.7 时长显示修正

超过一天的时间段以前会显示成 `0d Xh`，现在会正确显示天数。

## 三、命令行参数

直接运行 `hypercode`（不带子命令）启动的就是 TUI。本次升级新增或扩大了以下参数的适用范围：

| 参数 | 说明 |
| --- | --- |
| `hypercode --auto` | 启动时自动批准未被明确拒绝的权限（危险操作，请确认风险后再用）。本次新增 |
| `hypercode --yolo` | 隐藏参数，等价于 `--auto`。本次新增 |
| `hypercode --dangerously-skip-permissions` | 隐藏参数，等价于 `--auto`。`run` 上原本已有，现在启动 TUI 也支持 |
| `hypercode --mini` | 启动精简版交互界面。本次新增，TUI 与 `run` 都支持 |
| `hypercode --no-replay` | 精简界面在恢复会话或调整窗口后不回放历史。本次新增 |
| `hypercode --replay-limit <N>` | 限制精简界面回放的最新消息条数。`run` 上原本已有，现在启动 TUI 也支持 |

### 3.1 CLI/TUI 中文文案一致化

- 中文语言环境下，`hypercode --help` 及所有子命令帮助中的标题、简介、选项说明和 Yargs 框架标题统一显示简体中文。
- TUI 的命令面板、权限确认、问题提问、提示输入、状态栏、子智能体和工具输出统一使用当前语言设置；英文环境保留英文文案。
- 命令名（例如 `/commit`）、协议名、Provider/Model ID、工具名、路径、URL 和参数值保持原样，便于复制、搜索和诊断。

## 四、模型与供应商

- 新增可以直接登录的供应商：Cerebras、Modal、Snowflake Cortex，会出现在 `hypercode auth login` 的可选列表里。
- Azure OpenAI：修正端点与部署式 URL 的拼接方式，并调整推理参数的发送逻辑，减少因参数不受支持而报错的情况。
- Cloudflare AI Gateway：支持原生透传。
- GitHub Copilot：可用模型变体改为依据 Copilot 自身的能力接口判断。

## 五、Agent 能做的事更多了

- **读取 MCP 资源**：连接 MCP 服务器后，Agent 现在可以列出并读取该服务器提供的资源，也能处理带参数的资源模板；PDF、图片等类型的资源可以直接作为附件进入上下文。此前只能使用 MCP 提供的工具，用不到资源。
- **实验性脚本编排**：需要设置环境变量 `OPENCODE_EXPERIMENTAL_CODE_MODE` 才会启用。启用后，Agent 多了一个 `execute` 工具，可以运行一段受限脚本，批量编排已连接的 MCP 工具。

## 六、VS Code 扩展

### 6.1 扩展完整支持中英文

- 扩展跟随 VS Code 的显示语言：所有 `zh*` 语言环境显示简体中文，其余语言显示英文。
- 命令面板、设置说明、通知、输入框、状态栏、会话树、会话面板，以及 Todo、Modified Files、Subagents 侧栏均使用同一语言。
- 命令 ID、设置 key、路径、URL、快捷键、Provider/Model ID、Agent、Skill 和 MCP 名称保持原样，便于复制、搜索和诊断。
- 第三方返回的原始错误保留原文，HyperCode 提供的解释和操作提示会按当前语言显示。

### 6.2 切换扩展语言

在 VS Code 命令面板运行 `Configure Display Language`（“配置显示语言”），选择中文或英文后重载窗口。扩展语言会在重载后生效，不提供独立于 VS Code 的语言设置。

### 6.3 扩展版本与安装包

本次扩展版本为 `1.18.30`，对应安装包为 `hypercode.vsix`。安装本地 VSIX 后，可以在扩展详情页确认版本号。

## 七、怎么确认自己已经升级

```bash
hypercode --version
```

## 说明

- 本文整理的是上游 OpenCode 1.17.3 → 1.18.30 区间内、普通用户可感知的变化。
- 本次升级不包含破坏性变更；上游在此区间的其余改动以缺陷修复和内部重构为主。
- 上游在同一区间还有大量面向 Web、桌面等形态的改动，这些产物不在 HyperCode 当前交付面（`hypercode.exe` 与 `hypercode.vsix`）内，因此未列入本文。
- 想了解 OpenCode 与 HyperCode 的整体能力对照，请看 [OpenCode 与 HyperCode 功能总览](OpenCode与HyperCode功能总览.md)。
